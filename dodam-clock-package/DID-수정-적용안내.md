# DID 날씨·가정통신문·급식 수정

## 사이트에 올릴 파일

기존 ssok4edu 저장소의 dodam-clock-package 폴더에 다음 파일을 덮어씁니다.

- dodam-clock-did.html
- dodam-clock.html
- dodam-weather.json
- dodam-weather-feed.js
- dodam-notices.json
- dodam-notices-feed.js
- update-did-data.py
- update-notices.py

## 최신 자료 자동 갱신

github-actions/refresh-did-data.yml을 **저장소 최상위의 .github/workflows/refresh-did-data.yml** 위치에 올립니다. dodam-clock-package 내부에 넣으면 실행되지 않습니다.

GitHub Actions에서 Refresh Dodam DID data를 수동 실행해 첫 갱신을 확인합니다. 자동 갱신은 한국시간 기준으로 날씨를 매일 08:30·12:00·16:00에, 가정통신문을 09:00에 실행합니다. 예약 실행과 사이트 배포에는 지연이 있을 수 있습니다. 실패한 자료는 기존 파일을 보존합니다.

이 작업은 자료를 저장소에 반영합니다. GitHub Pages가 브랜치 배포 방식이면 기존 배포 설정을 확인해야 합니다. 별도 Actions 배포 방식에서는 GITHUB_TOKEN의 커밋이 후속 workflow를 시작하지 않으므로, 기존 Pages 배포 작업에 이 갱신 단계를 통합해야 합니다.

자동 갱신 없이 수동 운영하려면 PC에서 update-did-data.bat 실행 후 위 HTML 및 자료 파일 다섯 개를 다시 업로드합니다. PC에서 파일만 갱신하면 웹사이트에는 반영되지 않습니다.

## 변경 내용과 확인

- 두 HTML 모두 인터넷 시간 서버(TimeAPI)의 UTC를 받아 한국 시각으로 표시합니다. PC 시계나 시간대를 바꿔도 동기화 이후 표시는 영향을 받지 않습니다. 최초 연결 전에는 `--`로 대기하며, 동기화 후 연결이 끊기면 마지막 수신 시각에서 계속 진행합니다. 5분마다 다시 동기화합니다.
- SchoolClockPlus 안에서 열리면 프로그램의 KRISS 표준시를 사용합니다. HTML 단독 실행 시에는 인터넷 연결이 필요합니다.
- 구형 IE 계열에서는 같은 사이트의 날씨 자료를 먼저 읽습니다. 외부 API 연결이 막혀도 사이트 자료를 사용할 수 있습니다.
- JSON 읽기에 실패하면 같은 사이트의 호환용 자료 스크립트를 다시 시도합니다.
- 유효한 가정통신문 자료를 받았으면 불필요한 외부 RSS 재연결로 연결 지연을 표시하지 않습니다. 7일을 넘긴 자료와 수신 실패는 계속 오류로 처리합니다.
- 구형 DID HTML은 한국 시각 오전 9시 이후 가정통신문을 하루 한 번 확인합니다. 실패하면 15분 뒤 재시도하며, 저장된 제목이 오래됐어도 마지막 자료를 보여줍니다. 연결 지연 문구와 수신 날짜는 표시하지 않습니다.
- DID 화면은 계속 켜 두면 08:30·12:00·16:00에 날씨 갱신을 한 차례 시도합니다. 중간에 켜면 현재 시간대의 날씨를 확인합니다. 마지막 수신 자료는 최대 24시간 표시합니다.
- 구형 DID에서 사이트 배포가 늦으면 예약 시각부터 최대 1시간 동안 10분 간격으로 같은 사이트의 날씨 파일만 다시 확인합니다. 해당 시간대의 새 자료를 받으면 확인을 멈춥니다.
- 구형 DID HTML에서 스페이스를 누르면 날씨 → 급식 → 가정통신문 → 학사일정 순으로 다음 화면을 30초간 표시합니다. 급식 화면의 다음 배식일 미리보기는 표시하지 않습니다.
- 구형 DID HTML은 매초 변하지 않는 크기 스타일을 반복해서 적용하지 않도록 조정했습니다.
- 저장 날씨에는 수신 시각을 표시합니다. 24시간을 넘긴 자료는 현재 날씨로 사용하지 않습니다.
- 오늘부터 62일 범위에서 실제 급식이 있는 가장 가까운 날짜를 본문으로, 그다음 배식일을 아래에 표시합니다. 주말·공휴일·학교 재량휴업일도 배식 등록 여부에 따라 건너뜁니다.
- 업로드 후 DID 페이지를 새로고침합니다. 이전 화면이 남으면 브라우저 캐시를 지우고 다시 엽니다.
- DID에서 사이트 자체의 HTTPS도 열지 못하는 경우에는 기기의 인증서·TLS 지원 확인이 필요합니다.

코드 검증: node check-did.cjs. 표준시·가정통신문 화면 검증: node .schoolclock-build/verify-html-clocks.cjs. 구형 DID 실기기 검증은 별도로 필요합니다.
